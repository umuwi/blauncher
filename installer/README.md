# BLauncherSetup.exe — установщик лаунчера

Установщик для игрока: один exe, внутри которого уже лежит сам лаунчер, а тяжёлая часть добирается
с сервера.

```
installer/BLauncherSetup.cs     исходник (C# 5, WinForms, без внешних библиотек)
installer/app.manifest          asInvoker + DPI-осведомлённость
installer/BuildInfo.g.cs        генерируется сборкой — версия по умолчанию
installer/setup-shot.ps1        снять окно установщика в PNG (для проверки вида)
build-installer.ps1             сборка build\BLauncherSetup.exe и build\BLauncherSetup-uninstall.exe
build/BLauncherSetup.exe        результат: ~38 МБ, внутри — вшитая сборка
build/BLauncherSetup-uninstall.exe  маленький (~148 КБ) exe без вшитой сборки
```

Требуется .NET Framework 4.5 или новее (в Windows 10/11 он есть из коробки): распаковка zip идёт
через `System.IO.Compression.ZipArchive`. На машине с одним лишь 4.0 установщик честно скажет об этом
сразу, а не после скачивания десятков мегабайт.

## Что внутри exe и что качается

| Часть | Где лежит | Размер |
| --- | --- | --- |
| `BLauncher.exe` + `app\` (сам лаунчер и его библиотеки) | **внутри установщика** | 37,6 МБ в архиве |
| `runtime\` (встроенная Java) | качается с сервера: `downloads/blauncher.zip` | 55 МБ |
| полная сборка `downloads/BLauncher_<версия>.zip` | только запасной путь, если `blauncher.zip` нет | 93 МБ |

Имя скачиваемого файла — просто `blauncher.zip`, без версии: версия лаунчера и так живёт внутри exe.
Внутри лежит ровно то, что не вошло в exe, — папка `runtime\` (286 файлов). Вшитая часть
распаковывается мгновенно и без интернета. Если `blauncher.zip` на сервере почему-то нет, установщик
пробует `BLauncher_runtime_<версия>.zip`, а затем полную сборку — установка всё равно пройдёт.

## Что делает установщик

1. Спрашивает у сервера `https://blauncher.ru/update/manifest_pc.json` актуальную версию и проверяет,
   какие архивы этой версии реально лежат на сайте.
2. Показывает окно: папка установки с кнопкой **Обзор…** и тумблеры «Ярлык на рабочем столе»,
   «Ярлык в меню «Пуск»», «Запустить BLauncher после установки» (все три включены по умолчанию),
   плюс полосу прогресса со скоростью загрузки.
3. Распаковывает вшитую часть, затем докачивает `runtime\`. Обрыв связи больше не начинает загрузку
   с нуля: файл докачивается с места обрыва (HTTP Range), а если системный прокси еле тянет
   (медленнее 300 КБ/с дольше 12 секунд), установщик сам переходит на прямое соединение — на живой
   машине это разница между 140 КБ/с с обрывами и 2,6 МБ/с.
4. Распаковывает **поверх** папки: файлы перезаписываются, чужое не удаляется — `launcher_root` с
   мирами, `config` с настройками и входом, логи игрока остаются на месте. Перед распаковкой закрывает
   работающий лаунчер этой же папки (чужие процессы не трогает).
5. Создаёт ярлыки, кладёт рядом `uninstall.exe` (это отдельная маленькая сборка того же установщика —
   удалять лаунчер вшитая сборка не нужна, а лишние 38 МБ в папке ни к чему) и `install.json`,
   прописывает удаление в «Программы и компоненты» (HKCU — права администратора не нужны).
6. По тумблеру запускает `BLauncher.exe` с рабочей папкой установки. Если ярлык создать не удалось
   (например, политика запрещает Windows Script Host), в окне будет сказано именно это, а не «создан».

По умолчанию папка установки — `%LOCALAPPDATA%\BLauncher`. Никаких паролей и адресов SSH внутри exe
нет: всё берётся по HTTPS, поэтому из установщика нельзя вытащить доступ к серверу.

Удаление — `uninstall.exe` в папке установки (и запись в списке программ) с ключом `/UNINSTALL`.
Игровые файлы и `config` сохраняются, если не включить тумблер «удалить и всё остальное». Если в
указанной папке нет файлов лаунчера, удаление отказывается работать — иначе оно сносило бы чужие файлы.

## Ключи

| Ключ | Что делает |
| --- | --- |
| `/DIR=<путь>` | папка установки (по умолчанию `%LOCALAPPDATA%\BLauncher`) |
| `/ZIP=<файл>` | поставить из локального zip-файла, к серверу не обращаться вовсе |
| `/NODESKTOP` | не создавать ярлык на рабочем столе |
| `/NOSTARTMENU` | не создавать ярлык в меню «Пуск» |
| `/LAUNCH` / `/NOLAUNCH` | запускать ли лаунчер после установки |
| `/S` | тихая установка без окон (лаунчер не запускается, добавьте `/LAUNCH`) |
| `/UNINSTALL` | удалить лаунчер (`/REMOVEDATA` — вместе с `launcher_root` и `config`) |
| `/?` | справка |

Коды возврата: `0` — успех, `1` — ошибка, `2` — отменено. Ход установки пишется в
`%TEMP%\BLauncherSetup.log` — этот файл стоит просить у игрока, если что-то не встало.

Примеры:

```powershell
# обычная установка в папку игрока
.\build\BLauncherSetup.exe

# массовая установка в компьютерном клубе, без запуска лаунчера
.\build\BLauncherSetup.exe /S /DIR=D:\Games\BLauncher

# тихая переустановка в сети без интернета — из заранее скачанного архива
.\build\BLauncherSetup.exe /S /ZIP=C:\dist\BLauncher_1.12.5.zip /LAUNCH
```

## Сборка

```powershell
pwsh -File build-installer.ps1                      # собрать оба exe
pwsh -File build-installer.ps1 -Version v1.12.6     # вшить другую версию по умолчанию
pwsh -File build-installer.ps1 -Upload -SshPassword '...'   # собрать и залить в /var/www/blauncher.ru/downloads
```

Что делает скрипт:

1. Берёт версию из `manifest_pc.json` (локального, иначе с сервера) и проверяет, что на сайте есть
   и полная сборка, и `BLauncher_runtime_<версия>.zip`.
2. Собирает вшитую часть из `dist\BLauncher` (`BLauncher.exe` + `app\`) в `build\installer-core.zip`.
3. Компилирует **два** exe: маленький `BLauncherSetup-uninstall.exe`, затем основной
   `BLauncherSetup.exe` с двумя ресурсами — вшитой сборкой и маленьким exe для распаковки в папку.
   Компилятор — `csc.exe` из .NET Framework, C# 5: интерполяции строк, `nameof` и null-условного
   оператора в исходнике быть не должно.

Отдельный архив для новой версии нужен только если менялся runtime (встроенная Java). Собирается на
сервере из лежащей там полной сборки:

```sh
cd /var/www/blauncher.ru/downloads
unzip -q BLauncher_1.12.6.zip 'runtime/*' -d /tmp/rt
(cd /tmp/rt && zip -qr /var/www/blauncher.ru/downloads/blauncher.zip runtime)
chown www-data:www-data blauncher.zip
```

## Ссылка на скачивание на сайте

Кнопка «Скачать» на главной (`index.html`) ведёт на `/api/download.php?file=BLauncherSetup.exe` —
это тот же счётчик скачиваний, что и раньше, просто теперь он считает установщик. Для этого в
`api/download.php` расширен список разрешённых имён, а в `api/downloads.php` — шаблон подсчёта из
логов nginx (файл `blauncher.zip` намеренно не считается: это догрузка, а не скачивание продукта).
Бэкап страниц перед правкой: `/root/site-backup-installer/`.

## Что проверено

- ссылка «Скачать» на главной отдаёт установщик (302 → `/downloads/BLauncherSetup.exe`), счётчик
  скачиваний отвечает; скачанный по этой ссылке файл совпал по sha256 с локальной сборкой;
- установка этим файлом: код возврата `0`, 306 файлов, 195 МБ за ~26 секунд — вшитая часть
  распаковалась, `blauncher.zip` скачался с сервера (в логе видно использованный адрес);
- ярлыки на рабочем столе и в «Пуск» созданы, лаунчер запускается по ярлыку, удаление возвращает `0`
  и оставляет `launcher_root` с `config`;
- `uninstall.exe` в папке установки — 148 КБ (маленькая сборка), а не копия 38-мегабайтного установщика;
- обрыв связи и медленный прокси: загрузка продолжается с места обрыва, а при скорости ниже
  300 КБ/с установщик переходит на прямое соединение (в логе видно обе попытки);
- установка из локального zip: код возврата `0`, ярлыки указывают на установленный exe с правильной
  рабочей папкой, запись в «Программы и компоненты» на месте;
- защита от ошибок в пути: `/DIR=C:\` и `/DIR=C:` отвергаются (код `1`) — раньше `C:\` превращался
  в `C:` и установка уезжала в текущую папку процесса;
- защита при удалении: `/UNINSTALL /S /DIR=<чужая папка>` возвращает `1` и ничего не удаляет;
- окна установки и удаления сняты и проверены (`installer/setup-shot.ps1`): вёрстка, тумблеры,
  полоса прогресса, кнопки;
- иконка, манифест (`asInvoker`) и версия внутри собранного exe.

Скриншот окна снимается так (окно открывается, снимается и закрывается):

```powershell
pwsh -File installer\setup-shot.ps1 -Out "$env:TEMP\setup.png" -TitleMatch 'Установка BLauncher'
```
